# Better Endfield Next Android

本目录提供 Android ARM64 的 LSPosed 模块、设置应用和游戏内悬浮面板。当前 Android 源码版本为 `4.1.9`（versionCode `40109`），选择性接入上游 4.1.9 的创意工坊入口，应用包名为 `dev.betterendfield.next`；本地派生分支继续保留内置第一人称、陀螺仪、第三方模块入口和 Compose 设置界面。当前产品边界见[产品边界](../docs/PRODUCT_BOUNDARY.md)。

本次上游合并使用 Next 身份。旧包名 `dev.betterendfield.android` 与 Next 是两个独立应用，安装不会迁移旧应用设置或框架作用域；请在框架中启用 Next 并重新选择实际游戏作用域。不要同时对同一游戏启用两个模块。可先保留旧应用及数据，完成新包验证后再决定旧应用处理方式。

本地 Debug 与 Release 继续使用各自的固定签名配置；并未采用上游维护者的 Release 私钥。相同包名的更新仍需使用相同签名。此分支源码、宿主检查和 APK 构建结果不能替代设备运行与用户视觉验收。

## 使用要求

- Android 10 及以上、ARM64，以及支持 libxposed API 102 的框架环境。
- 作用域需包含实际安装的游戏包名。预选包名包括 `com.hypergryph.endfield` 和 `com.gryphline.endfield.gp`；其他渠道请按实际包名设置。
- 第一人称内置头饰目录使用完整 `v3` 清单：游戏 versionCode `61`、共 `898` 份资源。渠道、客户端版本和逐角色效果仍需分别验证。

## 安装与配置

1. 从 [正式发行页](https://github.com/Venshell/better-endfield-fixed/releases/latest) 下载 APK，安装后在框架中启用 Next 并设置游戏作用域。缓降实验包在 [Actions](https://github.com/Venshell/better-endfield-fixed/actions/workflows/android-build.yml?query=branch%3Aexperimental%2Fandroid-glide) 的对应运行中下载。
2. 打开应用配置所需模块，再完整重启游戏。
3. 进入游戏后用悬浮面板操作自由镜头、时间暂停、第一人称和 MMD 等功能。
4. 设置与运行日志可以从应用导出。排查时请同时保留失败时间、应用版本、游戏版本和相应日志。

首页的“游戏管理”卡片会列出已安装的受支持游戏；若安装了两个版本，需先选定目标。卡片正下方是“启用功能一览”。打开游戏不需要 Shizuku；“申请作用域”会请求 LSPosed 将所选游戏加入 Next 的作用域。“申请 Shizuku 授权”只在点击后发起，授权后才可用“停止游戏”。这些操作各自独立，首页不会自动申请权限或停止游戏。

PC 界面使用游戏自身的输入模式切换，默认关闭；部分触控控件会随游戏布局切换而隐藏。关闭悬浮面板与折叠面板的行为不同：折叠保留拖动手柄。

第一人称与陀螺仪继续由本地相机模块处理。头饰资源只决定已支持模型的隐藏与替换数据；完整清单校验不代表每个角色都已通过实机视觉验收。

## 模型与 MMD

BEM 管理器接受 BEM 文件、ZIP 单模型包和包含多个 BEM 的 ZIP 合集。导入合集后先选择要安装的包。应用按角色或武器目标展示，平台兼容、资源冲突和选项合法性由模型 owner 校验。

包选择保存使用安装索引修订号：列表已被其他入口更新时，旧草稿会被拒绝，需刷新后重新操作。游戏内局部编辑与设置应用保存共用同一校验和提交 owner。

原样导入保留包内容。模型管理页提供组合、预览、作者默认参数恢复、批量法线修复和明确的 ASTC 转换；存在未保存草稿时先保存选择，再使用这些操作。关闭本地副本时，预览和组合从框架中的对应代际读取，仍须通过索引长度校验。转换先发布新代际并提交索引，再退役旧文件，失败不能破坏原包。

模型实验区集中提供热切换、加载优化、关闭模型校验、克隆支持和释放旧模型资源；不能用关闭校验掩盖错误平台或不完整输入。管理员外观入口位于“角色”页，可分别配置武器、角色形态和战斗特效；保存后在下次游戏启动读取。配置已保存、模块已启动和游戏内视觉效果是三种独立状态。

MMD 支持本地动作、表情、镜头和音频，以及作品目录、ZIP 和 7z。作品导入先显示识别方案，可选择作品、改名、调整各舞者动作/表情和镜头/音乐槽位，确认后才安装。文件通过框架共享文件空间发布，再复制到游戏自己的目录；应用私有路径不能直接当作游戏可读路径。导入失败、短读或框架断连不能记录为已安装。

第三方模块入口保留 ARM64 原生模块和可选离线网页界面。二进制更新、卸载和加载顺序变化需要重启游戏。模块作者仍负责自己的游戏接口、线程与状态恢复。

工具页可打开 Compose 会客室媒体屏设置，选择图片、轮播图片或 MP4 后保存，并冷重启游戏装载配置。投屏是手动操作：进入会客室后，在游戏悬浮面板的“会客室投屏”中点击“开始／结束投屏”；停止可恢复原画面，视频支持暂停和跳转。面板读取原生播放状态并显示屏幕绑定/解码等错误，提交指令不代表已播放。用户此前报告保存并进入会客室后仍是原画面，本轮运行验收状态见[入口续接记录](../docs/ANDROID_UI_ALIGNMENT_20261109.md)。模型面板同样从原生读取当前已加载的动效列表，可控制开始、暂停、停止和速度；切换模型后旧控制令牌失效。

工具页的创意工坊入口打开应用内页面，分别展示直连与域名地址，支持复制和浏览器打开；断网时地址仍可查看与复制。关于页提供语言切换、软件更新、资源包导入与更新、项目和许可证链接，并增加原作者 [Dr-hydra/Better-Endfield](https://github.com/Dr-hydra/Better-Endfield) 的 GitHub 致谢入口。项目主页与许可证指向 [Venshell/better-endfield-fixed](https://github.com/Venshell/better-endfield-fixed)，软件更新检查读取本仓库的 Android APK 发行版本，基础资源更新仍按现有资源索引处理。原作者 Discord、群号和赞助入口不再保留。启动时自动检查可在关于页关闭。旧 View 版 MMD 作品页已由当前 Compose MMD 页及作品导入链取代。

## 游戏内悬浮窗

收起入口是浅色圆形齿轮，图案直径 42 dp，透明触摸区域为 56 dp。点按展开后入口保留在面板下层；横屏面板从左缘覆盖约 59% 的屏幕宽度，竖屏宽度不超过 320 dp。深色遮罩越过控件右缘后向右渐隐；顶部斜纹向下渐隐，右缘与遮罩同步渐隐；等高线顺时针旋转 90 度并贴住左下角。

面板保留现有功能分组。同行按钮根据卡片可用宽度等分，媒体控制在竖屏仍为单列。返回箭头位于标题左侧；点按面板外空白处也会收起，滑动空白处不会触发收起。展开和收起分别以 200 ms、160 ms 滑入淡入和滑出淡出；悬浮入口拖动松手或面板收起后以 180 ms 贴近最近的屏幕边缘，露出半个圆。自动贴边可在应用设置中关闭。

应用内「工具 → 悬浮窗」提供独立的「显示悬浮窗运行日志」开关，默认开启。关闭后只隐藏游戏内面板的日志区，日志记录与应用内日志页继续工作。游戏内面板底部不再显示热键来源说明。

面板在游戏窗口内启用硬件加速；Android 16 及以上按当前屏幕刷新率请求帧率。斜纹按面板尺寸预绘成位图，隐藏的控件面板保持已测量状态，并提前准备固定的控件分组。等高线素材来源见[第三方声明](../THIRD_PARTY_NOTICES.md)。

## 本地构建

需要 JDK 21、Android SDK platform 37、NDK `27.2.12479018`、CMake、Dobby 及已安装的 Gradle 依赖。工具路径与构建目录通过仓库工作区配置解析；构建产物、缓存和临时文件应放在配置的外部目录。

头饰资源必须提供完整且已校验的 `898/v61` 目录。示例从仓库根目录执行：

```powershell
$catalog = 'D:/codexdata/bem-headwear-v61-20261017/catalog'
.\android\gradlew.bat -p android :app:assembleDebug "-PheadwearCatalogDir=$catalog" --offline
```

构建会验证每份资源的哈希及清单覆盖范围；缺少资源会直接失败。CI 需显式提供当前头饰归档来源，不能回退到旧 `834` 份资源包。本机准备的完整归档可用 `tools/Camera/fetch_android_headwear_catalog.py --archive <归档路径>` 导入；在线来源使用该工具的显式参数或 `HEADWEAR_CATALOG_URL`。

Debug 签名读取 `android/keystore/debug.properties`，Release 签名读取 `android/keystore/release.properties`。Release 私钥不提交仓库；不能用临时生成的密钥替代现有发行身份。生成的源码、资源包和 APK 均通过构建任务产出。
